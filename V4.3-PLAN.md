# Wallet V4.3 implementation plan

This plan consolidates the requested changes on top of V4.2. Follow [ROADMAP.md](ROADMAP.md) for product rules and existing version scope. Planning alone does not authorize implementation.

## Records and account screens

1. **Search spacing:** Add clear spacing between the search icon and its text in the Records header, in both compact and expanded states where applicable.
2. **Today/month summary:** Make the Records Today label a clear, accessible toggle between today's and the current month's Income, Expenses, and Net totals. Update the displayed label and period with the selected mode. Start with Today, preserve the chosen mode through screen recreation, and refresh it when the date changes. The dated records list remains separate from the summary. Exclude transfers from income and expense totals.
3. **Day separation:** Give Records date headings stronger contrast and more obvious separation between days in light and dark modes, while keeping the existing chronological grouping.
4. **Add actions:** Remove the duplicate plus from Add record and audit other add actions for the same issue; show a single plus per action.
5. **Account rows and history:** Show opening balance only in the account editor. Remove the opening-balance text from the account list and the opening-balance row from account history, retaining the underlying value for balance calculations and backups. Reposition the current balance and Edit action to use the available space.

## Analysis screens

6. Remove the **Detailed analysis** heading.
7. Rename the view selector options: Calendar to **Daily Breakdown**, Category Breakdown to **Category Expense Graph**, and retain **Flow Graph**.
8. Remove the **By category** list below the Flow Graph. Keep the category wheel's own list and its category-history access.
9. Remove account filtering from both the Flow Graph and Category Expense Graph. Their range totals, graph, wheel, category values, and related category history use all accounts. Keep the date-range selection and the existing Net/Income/Expenses flow behavior.
10. Display the current date range first and place a clearly actionable **Custom range** button below it, so its purpose is apparent.
11. Put a theme-aware outline around each Income/Expenses/Net summary group in Analysis, including the monthly and detailed range summaries.
12. Increase the calendar grid border width consistently in light and dark modes, with sufficient contrast in each theme.

## Category wheel and compact amounts

13. Draw a thin, theme-aware outline around wheel sectors so adjacent slices are distinguishable in both themes. Preserve the existing negative-net-only categories, colors, values, and proportional slice sizes.
14. While a finger is pressed on a wheel sector, show that sector's percentage of the total absolute negative net represented by the wheel. Dismiss it on finger release or touch cancellation; do not show it when touching the center hole or outside the wheel. Keep category values accessible to screen readers.
15. Add **L** for lakh (100,000) to compact INR amounts, including the calendar, and update the displayed legend. Keep the other existing suffixes and exact stored values.

## Shared visual refinements

16. Restyle inconsistent buttons and top bars throughout the app to match its existing design language in both themes, including the Additional Icons button and screen header. Preserve their actions and accessibility.
17. Remove visible names beneath category icon choices in the category editor and Additional Icons screen. Retain meaningful accessibility labels; keep actual category names in transaction and category displays.
18. Add an icon beside the Dark mode setting, consistent with the app's line-art icon style and theme colors.

## Proposed defaults to review

- **Records monthly summary:** Use the full current calendar month, matching the existing Analysis monthly overview. This includes any future-dated transactions in that month. The toggle starts on Today.
- **Lakh abbreviation:** Use L for 100,000 through amounts below 1,000,000, then retain the existing M, B, and T suffixes for larger amounts. Keep K below 100,000 and preserve the existing compact rounding policy.
- **Wheel percentages:** Calculate each displayed percentage from the absolute values of the negative-net categories shown in the wheel. Percentage display is temporary and does not alter the underlying amounts.

## Suggested implementation order

1. Adjust shared button/header styling, search spacing, category icon labels, and the Settings icon.
2. Update Records summary mode, day headings, add actions, and account display layout.
3. Update Analysis labels, all-account scope, summary boxes, custom-range layout, and calendar borders.
4. Add compact lakh formatting, then improve wheel sector outlines and press-and-hold percentage feedback.
5. Update documentation and V4.3 version metadata.

## Validation on implementation

- Verify Today/month totals against known transactions, including transfers and month boundaries, and verify both modes across recreation and date changes.
- Check all-account Analysis calculations, category-history navigation, range changes, and the absence of the category list beneath Flow Graph.
- Exercise wheel sector hit testing, release/cancellation behavior, percentages, empty data, and small slices in both themes.
- Check compact values around 100,000 and 1,000,000, including negative values, rounding boundaries, and large exact amounts.
- Verify existing opening balances still affect account totals and remain editable, despite being hidden from account lists and history.
- Review light/dark screens, narrow layouts, larger text, touch targets, and screen-reader labels. Run the applicable existing tests, build, and lint checks when implementation is requested.

## Scope boundaries

- Keep account balance and transaction data unchanged; opening-balance visibility is a presentation change.
- Do not add CSV import, budgets, app lock, account-specific financial behavior, or unrelated features.
- Do not edit `AGENTS.md` without the approval required by its working rules.
