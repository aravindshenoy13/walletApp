# Wallet V4.3.2 implementation plan

This plan consolidates the four requested refinements after V4.3.1. Follow [ROADMAP.md](ROADMAP.md) for existing product rules. The current working tree already contains app changes; preserve and review them before implementation. This document does not itself authorize implementation.

## Requested changes

1. **Action button outlines and sizing**
   - Correct the colored outline so it is visible on all four sides of Add, Save, and Delete buttons, including Add category.
   - Fix inconsistent button dimensions, clipping, alignment, and padding. Retain unfilled backgrounds and the existing blue Add, green Save, and red Delete icon/text/outline scheme.
   - Check narrow screens, larger text, enabled/disabled states, and minimum touch targets in both themes.
2. **Brighter pastel category colors**
   - Brighten the displayed pastel category backgrounds, with particular attention to the dark-mode palette shown in the reference. Keep the eight normal colors distinct from the eight pastels.
   - Preserve the 16 existing color keys, saved category choices, and light-mode appearance. Keep the dark-mode line art readable against the brighter backgrounds; avoid simply darkening the pastels back to their current muted appearance.
   - Apply the display treatment consistently to category selection, category badges, and the wheel wherever they use the shared category colors.
3. **Dark-mode transfer colors**
   - Restore the intended earlier dark-mode transfer appearance for its icon and amount, and background if the previous appearance used one. Keep light-mode transfer colors unchanged.
   - Compare the pre-V4.3.1 implementation, available screenshots or built artifacts, and current in-progress changes before choosing values. The committed V4.3 resources do not clearly define a separate dark transfer amount color; confirm the visual target if those references do not establish it.
4. **Category list label**
   - Remove the visible “Custom” label from category rows. Keep category names, icons, editing, and any meaningful archived-state indication.
   - Preserve the built-in/custom distinction in stored data and backup behavior; this is a display change.

## Implementation sequence

1. Review the existing V4.3.1 working changes and identify the shared action-button drawable/style and layout constraints causing the outline and sizing issues.
2. Correct action-button rendering, then refine the dark-mode pastel display treatment and transfer colors using the agreed visual reference.
3. Remove the Custom row label without changing category data or actions.
4. Update V4.3.2 documentation and verify the existing version metadata rather than overwriting unrelated working changes.

## Validation when implementation is requested

- Build the debug app and run the applicable existing checks. Review Add, Save, and Delete buttons in light and dark mode, including small widths and larger text.
- Inspect all pastel swatches and representative category badges in dark mode for brightness, differentiation, selection visibility, and readable icon contrast; confirm stored color choices remain unchanged.
- Compare transfer icon and amount colors in dark mode to the selected earlier reference and verify light mode remains unchanged.
- Verify category rows omit Custom while archived categories remain identifiable, and category edit/archive and backup behavior continue to work.
- Use the selected visible device for UI review and preserve existing app data and unrelated working-tree changes.
