# Wallet V4.4 implementation plan

This plan consolidates the V4.4 requests on top of V4.3.2. Follow [ROADMAP.md](ROADMAP.md) for existing product rules. Review and preserve the current in-progress working-tree changes before implementation; this plan does not itself authorize implementation.

## Scope

1. **Bottom navigation icons:** Make Records, Analysis, Accounts, and Categories icons visually consistent in size, stroke weight, and alignment. Check their visible artwork bounds as well as drawable dimensions, while preserving labels, selection indication, and touch targets.
2. **Reported crashes:** Reproduce and diagnose the crashes from **Add record** and the **Categories** button. Inspect the actual exception and fix its cause rather than assuming the two crashes have the same cause. Preserve existing wallet data and use disposable test data where needed.
3. **Search appearance:** Reproduce the Records screen becoming brighter after searching when there are no records. Fix the theme/overlay or state issue identified by investigation so dismissing search restores the normal appearance without needing to tap Search again. Preserve live filtering, Clear, and the Today/month summary behavior.
4. **App-wide design review:** Review screens and controls for places that do not follow the established simple design language, including spacing, headers, buttons, icons, selection states, and light/dark themes. Correct missed inconsistencies without adding unrelated features or changing financial calculations.

## Implementation order

1. Record the current V4.3.2 baseline and reproduce the two reported crashes and the empty-record search appearance issue; capture relevant error details without exposing wallet data.
2. Fix the confirmed crash causes, then fix the search appearance and dismissal behavior.
3. Normalize bottom navigation icons and review the remaining screens against the established app styling.
4. Update V4.4 version metadata and documentation after the changes are complete.

## Validation when implementation is requested

- Verify Add record and Categories open without crashing from an empty wallet and from a wallet containing accounts and transactions; exercise their existing save/edit paths with disposable data.
- In light and dark mode, open search with no records, enter a query, and dismiss or clear it using the available controls. Confirm the screen returns to its normal appearance without a second Search tap. Also check searching with records and with no matching result.
- Review navigation icon size and alignment and the app-wide design changes at normal and larger text sizes. Preserve accessibility labels, selection semantics, and touch targets.
- Run applicable existing tests, debug and release builds, and lint checks. Keep backups, balances, transactions, category data, and V4.3.2 behavior intact.

## Scope boundaries

- The reported crash scope is Add record and Categories; the user withdrew the earlier report that every button crashes.
- Do not add CSV import, budgets, app lock, or unrelated features. Do not change `AGENTS.md` without its required approval.

## Implementation — 12 November 2026

- Preserved the pre-existing V4.3.2 working changes in a separate local checkpoint. The original diff and baseline crash logs are retained under `repository/.tools/v44-qa/`.
- Confirmed both reported crash paths independently in the emulator's exception logs: Add record failed in `RecordEditorActivity.refreshCategories`, and Categories failed in `CategoriesAdapter.onBindViewHolder`. Both reached `ColorUtils.calculateContrast` with a blended background whose alpha had rounded from 255 to 254. Blended display colors now explicitly retain alpha 255. All 16 color choices are tested in both themes, including the existing dark-mode contrast threshold; stored choices are unchanged.
- Removed the priority-overlay Back callback from search. Normal IME/Android Back handling and a visible-to-hidden keyboard transition now collapse search, clear its query and focus, and return focus to the main root. Back, Done, outside tap, leaving, and direct keyboard dismissal use the same cleanup; Clear keeps the field open. Records explicitly paints its themed background.
- Baseline Back/Done/outside screenshots did not reproduce persistent whole-screen brightening; direct keyboard hiding did reproduce search remaining expanded. Final screenshots verify the same background pixels before searching, after Clear, and after each dismissal in both themes. Confirmation of the originally reported visual symptom on the reporting device remains a validation limit.
- Navigation uses dedicated 24 dp vectors with a 1.6 viewport-unit stroke, centered artwork with comparable visible bounds, and equal-height touch targets. The category badge icon remains unchanged. Labels, bold selected state, accessibility semantics, and single/multiple selection behavior are preserved.
- Secondary screen titles now share bold 20 sp themed typography, including Settings and Additional Icons. Settings' Dark mode control has consistent full-width spacing. Date-range buttons can grow with larger text instead of clipping to a fixed height. Reviewed Records, accounts/history, analysis views, categories/editors, icon choices, Settings, export, and date controls; no new features were added.
- Version name is `4.4`, version code `10`. Room schema 3, backup format 2 and format-1 compatibility, CSV, saved data, and financial calculations are unchanged. `AGENTS.md` was not edited.
