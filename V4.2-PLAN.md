# Wallet V4.2 implementation plan

This plan consolidates the requested refinements on top of V4.1. Follow [ROADMAP.md](ROADMAP.md) for the existing product rules and the approved wireframes for the app's simple visual language. This document plans the work; it does not itself authorize implementation.

## Interface refinements

1. **Selection controls:** Replace visible default checkbox boxes and tick glyphs with wireframe-style selection states throughout the app. Use a clear border or background treatment for selected items, including category icon tiles, color swatches, Additional Icons, transaction types, Analysis choices, export choices, and Settings. Preserve single-choice and multi-choice behavior, touch targets, keyboard use, and accessibility state descriptions. Keep the category icon and its 16-color background independently selectable.
2. **Transaction type icons:** Resize and align the Expense, Income, and Transfer icons with their labels and selection surfaces so the three choices fit cleanly, including on narrow screens and with larger text.
3. **Settings entry:** Replace the gear beside the Wallet title with a three-line menu icon. Keep it aligned with the title and opening Settings.
4. **Category icon contrast:** Fix low-contrast category icons in dark mode, especially white line art over pastel backgrounds. Adapt the displayed colors as necessary for readability while preserving the user's saved icon and background-color choices.
5. **Category wheel in dark mode:** Improve the chart's dark-theme appearance, including slice distinction, contrast against the background, and center-label readability. Keep category associations, slice proportions, and the existing negative-net-only calculation.
6. **Account balance colors:** Display positive and zero account balances in the normal text color and negative balances in red. Apply this consistently wherever an account balance is displayed; retain the existing colors for income, expenses, and other net values.
7. **Add category:** Remove the duplicated plus sign so the action displays one plus icon.
8. **Settings screen:** Restyle the header/back control, actions, and dark-mode control to match the app's simple theme and wireframes in both light and dark modes. Keep the existing actions and behavior.
9. **Dropdowns:** Give dropdown fields throughout the app a thin, theme-aware box outline and a recognizable dropdown indicator. Cover Analysis selectors and account/transaction selectors, including their enabled, focused, and disabled states.
10. **Reduce explanatory clutter:** Remove redundant helper sentences where nearby headings, labels, or values already communicate the same information, including the selected-range summary explanation. Retain essential validation messages, confirmations, and information needed to make a financial or restore decision.
11. **Search dismissal:** Collapse expanded Records search when the user leaves or dismisses it, including Back and tapping outside. Proposed normal-state behavior: clear the query and restore the full records list on dismissal; the existing Clear action and live filtering remain available while search is open.
12. **Account icons:** Offer exactly three selectable visual icons—bank, cash, and card—when adding or editing an account. Show the chosen icon with the account in its list and detail views. The icon is a visual label; all accounts retain the same balance, overdraft, and transfer behavior.

## Account icon data and compatibility

- Persist the account's icon choice so it survives app restarts and can be edited. Give existing accounts a consistent bank-icon default rather than guessing from their names.
- Add a non-destructive Room migration from the current schema, preserving account IDs, opening balances, categories, transactions, transfers, and existing note data.
- Include the icon in new full backups and continue accepting existing V4 backup files, assigning the same default icon to accounts restored from older backups. Preserve the existing empty-wallet restore rule and atomic restore behavior.
- Keep transaction CSV behavior and format unchanged unless separately requested; an account icon is presentation metadata.

## Implementation order

1. Audit current checkbox/radio, icon, dropdown, and helper-text usage; introduce small shared theme-aware styles and selection states.
2. Apply the transaction-type, category selection, Settings, navigation, Add category, and dropdown refinements in both themes.
3. Improve dark-mode category badges and the category wheel, keeping calculations and stored colors intact.
4. Fix search dismissal and account-balance colors.
5. Add account icon selection, persistence, migration, and backup compatibility.
6. Update user-facing documentation and the version metadata for V4.2.

## Validation on implementation

- Check the affected screens in light and dark mode, including narrow layouts, larger text, selected/unselected states, keyboard navigation, and accessibility labels.
- Verify search open, live filtering, Clear, outside-tap and Back dismissal, and return to the normal records list.
- Verify account balance colors for positive, zero, and negative amounts; retain existing income/expense and net coloring.
- Verify the V4.1 wheel still includes only negative-net categories and retains its values and proportions.
- Verify an upgrade with existing accounts and transactions, editing and reopening all three account icons, restoring an older full backup with the default icon, and a new backup/restore round trip with selected icons.
- Run the applicable existing unit and Android flows plus build and lint checks for the implementation. Use a disposable emulator or test data for restore and migration checks.

## Scope boundaries

- Do not add account-specific financial behavior, budgets, app lock, or CSV import. These refinements do not change the existing transaction and transfer calculations.
- Do not edit `AGENTS.md` without the separate approval required by its working rules.
